# The documentation site

The site at [agenticterms.integraledger.com](https://agenticterms.integraledger.com): a [Fumadocs](https://fumadocs.dev)
app on Next.js, exported as static files and served by Cloudflare as a Worker's static assets.

It holds no documentation of its own. Its pages are the repository's [`docs/`](../docs), read in place, and API pages that
TypeDoc generates from the packages' TypeScript source at every build.

## What it serves

| Path | What it is |
| --- | --- |
| `/`, `/<page>` | Every page of `docs/`, with its sidebar order from each folder's `meta.json`. A request whose `Accept` header prefers `text/markdown` gets the page as Markdown. |
| `/api/terms`, `/api/terms-mcp` | The API reference, generated by TypeDoc from `agentic-terms/src` and `agentic-terms-mcp/src`. |
| `/llms.txt` | The index of every page, for AI agents ([llmstxt.org](https://llmstxt.org)). |
| `/llms-full.txt` | Every page as Markdown, in one file. |
| `/<page>.md`, `/index.md` | One page as Markdown, at its address with `.md` appended. The build writes each page's copy at `/md/<page>.md`. |
| `/api/search` | The static search index. |
| `/sitemap.xml`, `/robots.txt` | For crawlers. |
| `/.well-known/security.txt` | Where to report a vulnerability ([RFC 9116](https://www.rfc-editor.org/rfc/rfc9116)), under [`SECURITY.md`](../SECURITY.md). It expires 180 days after the commit the site is built from. |

Every TypeScript sample is type-checked by [Twoslash](https://twoslash.netlify.app) against the packages as they are
built in this repository, and the build fails on a type error. Hovering an identifier shows its type.

Each ```` ```mermaid ```` block is rendered to SVG at build time with the `mermaid` package, in a pinned Chrome Headless
Shell, once in a light and once in a dark theme. Every text is measured and drawn in Inter, from the
`@fontsource-variable/inter` package, and in no font of the machine's: the browser has a font configuration of its own
with no font in it, and its clock reads UTC and formats in the en-US locale. A diagram with a character Inter does not
draw fails the build. Both SVGs are in the page's HTML, and the page shows the one for the reader's theme; the site
serves the same Inter files, and no diagram code runs in the browser.

## Building

The site reads the built packages, so build them first, from the repository root:

```sh
pnpm install --frozen-lockfile
pnpm -r --if-present run build
```

Then, in this folder, which has its own lockfile and install policy:

```sh
pnpm install --frozen-lockfile
pnpm run browser   # fetch the browser that draws the Mermaid diagrams into .browser/, checked by its SHA-256
pnpm run build
```

The diagrams are drawn in one browser build: Chrome Headless Shell 156.0.8078.4 for Linux x64, the build the locked
`playwright-core` names, from Chrome for Testing's
[download bucket](https://googlechromelabs.github.io/chrome-for-testing/). `scripts/browser.mjs` holds its version, its
address and the SHA-256 of its archive; `pnpm run browser` fetches the archive, retrying five times after a network
error or an answer other than 2xx, checks it and unpacks it. The build uses no other browser: on a machine without it,
it stops and names that command.

The site is built on Linux x64, in CI or on a maintainer's Linux x64 machine. The browser build is pinned for that one
platform because a build for another platform measures text through that platform's own font engine, so its diagrams
could differ; on another platform the build stops and names the platform it is pinned for.

`node scripts/check-diagrams.mjs`, after the build, draws every diagram again under a font configuration that changes
every font's rendering and checks that the SVGs are the same, that a diagram with a character Inter does not draw is
refused, and that `out/` serves the Inter files the diagrams are drawn in.

The static site is in `out/`. `public/_headers` sets its response headers, and `wrangler.toml` deploys `out/` as a
Worker's static assets with the site's 404 page. `pnpm run dev` serves it locally while you edit `docs/`; it does not
run `worker.js`.

## How it is served

`wrangler.toml` serves `out/` as a Worker's static assets, with `worker.js` in front of the page addresses and their
`.md` addresses only:

- `/<page>.md`, and `/index.md` for the home page, answer with the page's Markdown copy (the address
  [llmstxt.org](https://llmstxt.org) proposes). `/llms.txt` links each page there.
- A request for a page whose `Accept` header ranks `text/markdown` (or `text/x-markdown`) at least as high as
  `text/html` gets the same Markdown at the page's own address; `text/plain` is not a Markdown type and gets HTML. A
  page address that ends in a slash redirects to the address without it, for Markdown as for HTML. Every response for
  a page address carries `Vary: Accept`, and a conditional request for a Markdown copy can be answered 304.
- Every other file is served directly, without the Worker: the Markdown copies, the scripts, the search index and
  every `.txt` file, the RSC payload each page fetches among them. Every response the Worker returns is a static
  assets response, so the rules in `public/_headers` apply to all of them.

Each page names `/llms.txt` with `<link rel="describedby">` and its Markdown with `<link rel="alternate"
type="text/markdown">`.
